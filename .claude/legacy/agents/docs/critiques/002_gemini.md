#!/usr/bin/env python3
"""
A robust, deterministic script to partition a flat marker-pdf JSON list into
a structured list of sections. Includes input validation and structured logging.
"""
import json
import sys
import logging
import argparse
from pathlib import Path
from typing import List, Dict, Any

# CRITIQUE: Use logging instead of print for better observability.
logging.basicConfig(level=logging.INFO, format='%(asctime)s - %(levelname)s - %(message)s', stream=sys.stderr)

def partition_document_by_section(nodes: List[Dict[str, Any]]) -> List[Dict[str, Any]]:
    """Transforms a flat list of nodes into a list of section objects."""
    if not nodes:
        return []
        
    structured_document = []
    current_section = None
    
    for i, node in enumerate(nodes):
        # CRITIQUE: Validate node structure to prevent crashes.
        if not isinstance(node, dict) or "type" not in node:
            logging.warning(f"Skipping malformed node at index {i}: {node}")
            continue

        if node.get("type") == "Header":
            current_section = {"section_header": node, "content": []}
            structured_document.append(current_section)
        elif current_section:
            current_section["content"].append(node)
        else:
            # CRITIQUE: Create a prologue section ONLY if content appears before the first header.
            logging.info("Content found before first header. Creating a 'Document Prologue' section.")
            current_section = {"section_header": {"type": "Header", "text": "Document Prologue"}, "content": [node]}
            structured_document.append(current_section)
            
    return structured_document

def main():
    """Main execution function with robust argument parsing and error handling."""
    # CRITIQUE: Use argparse for clear, documented CLI arguments.
    parser = argparse.ArgumentParser(description="Partitions a marker-pdf JSON file into sections.")
    parser.add_argument("input_file", type=Path, help="Path to the input flat JSON file.")
    parser.add_argument("output_file", type=Path, help="Path to write the output sectioned JSON file.")
    args = parser.parse_args()

    if not args.input_file.exists():
        logging.critical(f"Input file not found: {args.input_file}")
        sys.exit(1)

    try:
        logging.info(f"Reading from {args.input_file}...")
        with args.input_file.open('r', encoding='utf-8') as f:
            flat_nodes = json.load(f)
            
        logging.info("Partitioning document into sections...")
        structured_doc = partition_document_by_section(flat_nodes)
        
        logging.info(f"Writing {len(structured_doc)} sections to {args.output_file}...")
        with args.output_file.open('w', encoding='utf-8') as f:
            json.dump(structured_doc, f, indent=2)
            
        print("Stage 1: Partitioning complete.")
        
    except json.JSONDecodeError:
        # CRITIQUE: Handle JSON decoding errors gracefully.
        logging.critical(f"Invalid JSON in input file: {args.input_file}")
        sys.exit(1)
    except Exception as e:
        logging.critical(f"An unexpected error occurred: {e}", exc_info=True)
        sys.exit(1)

if __name__ == "__main__":
    main()

| **2. Cleaning Text (Ligatures, Encoding)** | **Heuristic (Python Worker)** | This is a mechanical find-and-replace operation. The rules are defined in a dictionary (e.g., `ﬁ` -> `fi`). A script is vastly more efficient and reliable for this than an LLM, which might hallucinate or misinterpret the characters. |
| **3. Merging Table Fragments** | **Heuristic (Python Worker)** | This is a "strong heuristic" task. The worker uses rules based on `bbox` coordinates, column counts, and keywords like `(continued)`. While an LLM *could* attempt this, it's inefficient for it to parse complex coordinate data. The Python worker is better suited to handle the geometric and structural analysis required, making it a well-placed heuristic task. |
| **4. Describing an Image** | **Semantic (Agent/LLM Call)** | **This is the most critical example of correct separation.** You correctly pointed out that my earlier version's heuristic (just finding a caption) was flawed. An image's content cannot be understood by rules. It requires true *seeing* and *reasoning*. Therefore, this task is correctly assigned to a **multi-modal agent** that can process the image data (base64 string or file) and the surrounding text to generate a meaningful description. This requires semantic understanding that a script cannot possess. |
| **5. Merging Contiguous Text Nodes** | **Semantic (Agent/LLM Call)** | This task is deceptively complex. A simple heuristic (`if node_A is text and node_B is text, merge`) is brittle and would make mistakes, such as merging a paragraph with a subsequent page number or a list item with an unrelated sentence. Correctly deciding if two blocks of text belong in the same paragraph requires **understanding the flow of the argument and the semantic relationship between the sentences.** This is a perfect task for an LLM's reasoning capabilities. |

### Why This Separation is the Optimal Approach

By dividing the labor this way, the pipeline gains several critical advantages:

1.  **Efficiency and Cost-Effectiveness:** The "heavy lifting" of mechanical, repetitive tasks (cleaning millions of characters, partitioning thousands of nodes) is handled by fast, cheap-to-run Python code. Expensive and slower LLM calls are reserved *only* for the tasks that genuinely require their advanced reasoning power. This saves an enormous amount of time and money.

2.  **Reliability and Determinism:** Heuristic tasks, when designed correctly, are 100% predictable. The partitioner will always partition the same way. The text cleaner will always fix the same ligatures. This reliability is crucial for building a stable data processing pipeline. The non-deterministic nature of LLMs is firewalled to only the tasks where that "fuzziness" is a feature (i.e., understanding natural language), not a bug.

3.  **Power and Flexibility:** The pipeline doesn't break when faced with ambiguity. Instead of writing incredibly complex and brittle Python rules to try and guess if two sentences belong together, we delegate that ambiguity to the component best suited to handle it: the LLM. This makes the system robust against variations in document style and layout.

4.  **Maintainability and Debugging:** This architecture is far easier to maintain. If table merging logic needs to be improved, you edit one focused Python worker script. If the quality of image descriptions needs to be enhanced, you refine the prompt sent to the multi-modal agent. This is much simpler than debugging a single, monolithic prompt or script that tries to do everything at once.

In summary, you have correctly pushed for a design that uses the best tool for each job. The final architecture correctly separates the "how" (the mechanical execution by worker scripts) from the "what" (the semantic decision-making by the reasoning agent).
